# 2026-09-07

## AI 标题生成拆分为两步（独立双模型）
用户确认设计：①图像识别（视觉模型）→ 输出对局信息文本；②标题生成（文本模型）→ 基于该信息创作标题。两点端各自独立配置 base_url/api_key/model/thinking/reasoning_effort（可不同服务商），前端一键两步自动串联，并把识别信息展示在视频条目上供事后核对。

### Rust 端
- `user_config.rs`：`AiConfig` 拆为 `{ enabled, ffmpeg_path, vision: AiEndpointConfig, writer: AiEndpointConfig }`；`AiEndpointConfig` 含 base_url/api_key/model/thinking/reasoning_effort。**自定义 Deserialize 兼容旧扁平字段**（ai.base_url 等一次性迁移到两端点）。`models/mod.rs` 导出 `AiEndpointConfig`。
- `ai.rs` 重构为两条命令：
  - `ai_analyze_video(app, video_path, prompt)` → `AiAnalyzeResult { info, reasoning }`：截帧 + vision 端点请求，temperature 0.2，不解析标题。
  - `generate_ai_title(app, info, prompt, on_reasoning)` → `AiTitleResult { title, reasoning }`：仅文本请求（info 作为 system 上下文），writer 端点，temperature 1.2。
  - 底层抽公共 `request_chat<F: FnMut(&str)>(endpoint, messages, temperature, on_reasoning)` 按 thinking 自动流式/一次性。**教训：async 命令里不要用 `&mut dyn FnMut` 参数（future 非 Send），改泛型闭包**。
- `lib.rs` 注册 `ai_analyze_video`。

### 前端
- `stores/utils.ts`：提示词常量拆分 `AI_VISION_PROMPT`、`AI_WRITE_PROMPT`（`AI_TITLE_PROMPT` 保留为 writer 别名）；新增 `analyzeVideo(videoPath, prompt)` 与 `generateAiTitle(info, prompt, onReasoning)`；新增 `AiAnalyzeResult` 类型。
- `stores/user_config.ts`：`AiConfig` 接口嵌套 vision/writer；`AiEndpointConfig` + `createDefaultAiEndpointConfig`；新增模块级 `buildAiEndpointConfig`；updateGlobalConfig 全量传输嵌套 ai。
- `GlobalConfig.vue`：AI 设置区分两个带编号的分组卡片（图像识别/标题生成），表单字段 ai_vision_*/ai_writer_*，ffmpeg 共用；hasUnsavedChanges/默认值/加载/保存同步更新。
- `VideoList.vue`：`runAiTitleForVideo` 串联 `analyzeVideo`→`generateAiTitle`；新增 `aiInfos` 状态 + `.ai-vision-info` 展示块（可 × 清除）；watch videos 变化清理失效本地状态；`isAiConfigured` 校验两端点均完整；handleRemoveFile 清识别信息。
